# Sol Flow 0.9.7

[Русский](release-0.9.7.md) · **English**

This version brings together the changes since the public 0.9.0 release
for Windows, Mac and Android. [Release page](https://github.com/isoloma-ux/solflow/releases/tag/v0.9.7).

## Changes since 0.9.0

- Faster dictation: lightweight text cleanup and a space between successive
  insertions. On desktop, deeper Qwen editing is available separately and
  can also be enabled before insertion. Android does not need a language model.
- Transcript preservation: the previous result is backed up before
  reprocessing, and edits are saved safely.
- Speakers: mixed and unidentified segments are marked, speakers can be
  assigned manually, and speaker names are included in exports.
- Working with recordings: audio playback, timestamp navigation, playback
  speed controls and easier access to transcripts and analyses.
- Recording maps: Mac and Windows generate a mind map locally from the
  transcript. All three platforms support viewing, editing and PNG/SVG
  export with the Sol Flow logo. Finished maps are shared through your
  configured sync service.
- Map styling: the Sol Flow light theme and a translucent logo in the
  bottom-right corner of the exported image.
- Clear map generation status, preview and error messages on desktop.
  Exports use the configured export folder. On Android, map controls stay
  clear of the system bars and adjust to the on-screen keyboard.

## App features

In addition to this release's changes, Sol Flow offers dictation into other
apps, meeting recording with pause, audio and video import, timestamped
transcripts, search, projects and text export. Sync uses your own
Yandex.Disk or Google Drive; audio transfer can be enabled separately.

Mac and Windows also generate summaries and titles, answer questions about
a recording, translate text and produce topic-based analyses: decisions,
tasks, follow-up letters, outlines, key points and other formats.
Speech recognition and AI processing run locally after the models have
been downloaded. Android does not run the large language model: summaries,
titles and finished maps can arrive from desktop through sync. Questions
about a recording and translations remain on desktop.

[Full feature overview and instructions](../README.en.md#what-it-does).

## Download and update

- [Windows x64, Windows 10 or 11](https://github.com/isoloma-ux/solflow/releases/download/v0.9.7/SolFlow_0.9.7_x64-setup.exe).
- [Mac with Apple silicon, macOS 14 or later](https://github.com/isoloma-ux/solflow/releases/download/v0.9.7/SolFlow_0.9.7_macOS.zip).
- [Android arm64, Android 8.0 or later](https://github.com/isoloma-ux/solflow/releases/download/v0.9.7/SolFlow_0.9.7.apk).

On desktop, click the version number at the bottom of the window. When
the update to 0.9.7 is offered, click again: the app downloads the update,
installs it and restarts. You can also download the installer above; on
Mac, move the app from the ZIP into Applications, replacing the previous
copy. On Android, install the APK over the existing app.
There is no need to uninstall the previous version first.

The app identifiers and existing signing keys are retained. If the test
version 0.9.7 is already installed on Android, the version number stays the same.

## Validation and limitations

At publication, the user had tested the app on Mac and a physical Android
16 phone. All three release builds completed successfully in GitHub
Actions. APK and desktop updater signatures, Mac archives, checksums and
public download links were verified. Manual Windows runtime testing is
still pending; a successful build does not replace that check.

The Mac build requires macOS 14 or later because of the bundled AI library.
This restriction was already present in 0.9.0; this build does not support
macOS 12–13.

Windows does not yet have Microsoft Authenticode signing. Mac uses the
existing Sol Flow certificate without Apple notarization. These are not
new app-store signatures. New users may see an operating-system warning
during installation. Maps are generated by a local model: check their
wording against the transcript.

## Release process

The tag is created after a successful build on main. The release and android
workflows upload files to a draft. Once both runs succeed, the APK, updater
signatures, Mac archive and latest.json for windows-x86_64/darwin-aarch64
are verified. Only then is the draft published and marked Latest.
