# Импорт медиа: версия 0.9.8

[English](media-import.en.md)

## Что изменено

- Mac сначала использует системное преобразование звука. Если контейнер или кодек не поддержан, подключает FFmpeg. Это исправляет импорт MPEG-TS/HLS, в том числе потоков Rutube, которые могут иметь расширение `.mp4`.
- Загрузчик предпочитает отдельную аудиодорожку. Если её нет, выбирает небольшую видеоверсию: изображение для расшифровки не требуется.
- Метаданные и медиа загружаются одним процессом. Исправлены блокировка обработки прогресса и риск зависания при заполнении вывода ошибок. Отмена останавливает дерево процессов; незавершённый файл не считается готовой записью.
- При ошибке преобразования скачанный оригинал сохраняется в папке записи, даже если хранение исходников отключено. При успешной обработке действует обычная настройка хранения.
- В настройках можно установить или обновить компоненты загрузки. На Mac и Windows Sol Flow хранит собственные yt-dlp, FFmpeg и Deno в `bin` внутри папки данных приложения. До замены проверяются контрольная сумма и запуск новой версии; повреждённая загрузка не заменяет рабочий файл.

## YouTube

Общедоступные видео часто скачиваются без аккаунта. Сообщение «подтвердите, что вы не бот» зависит также от сети/IP, VPN, ограничений ролика и проверок YouTube. Вход в браузере сам по себе не передаёт сессию приложению.

Сначала обновите загрузчик в настройках и повторите импорт. Если нужна авторизация, в поле ссылки YouTube выберите браузер, в котором открывается этот ролик. По умолчанию выбрано «Без аккаунта». Выбор действует на одну загрузку и затем сбрасывается; для других сайтов этот доступ не используется. Sol Flow передаёт yt-dlp только название выбранного браузера, не сохраняет cookies в записи и не синхронизирует их. Система или браузер могут не разрешить чтение сессии. Авторизация не гарантирует снятия ограничений YouTube.

[Официальная справка yt-dlp о cookies](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)

## Платформы

Изменения импортера относятся к Mac и Windows. Android по-прежнему импортирует локальные файлы, прямые медиассылки и Яндекс.Диск; загрузчик страниц YouTube/Rutube на телефон не добавлен. Готовые записи можно передавать обычной синхронизацией. Версия Android и история изменений согласованы с 0.9.8; Windows требует отдельной проверки на реальном компьютере.

## Компоненты и происхождение

- yt-dlp и Deno: официальные GitHub Releases, проверка SHA-256 из метаданных релиза. Standalone yt-dlp включает необходимые компоненты EJS; Deno запускается по явному пути.
- Windows FFmpeg: `yt-dlp/FFmpeg-Builds`, проверка SHA-256 опубликованного архива.
- Apple Silicon FFmpeg 7.1: `imageio/imageio-binaries`, commit `f8f64710ea88e7e4a352c0f7d8c0deac9f5fd685`, файл `ffmpeg/ffmpeg-macos-aarch64-v7.1`, SHA-256 `6d175a4743ca50256e89a8cdd731100f9cee33bd79aeea46894d209410dc6617`.

Бинарники скачиваются отдельно при установке компонентов и не включены в исходники приложения. Их лицензии остаются действующими: [yt-dlp](https://github.com/yt-dlp/yt-dlp#license), [Deno](https://github.com/denoland/deno/blob/main/LICENSE.md), [FFmpeg](https://ffmpeg.org/legal.html), [ImageIO binaries](https://github.com/imageio/imageio-binaries/tree/f8f64710ea88e7e4a352c0f7d8c0deac9f5fd685/ffmpeg).

## Проверка

Регрессионный сценарий `scripts/check-media-import.py` компилирует фактические модули загрузчика и проверяет ошибки, неполные файлы, прогресс и отмену. `SOLFLOW_TEST_DEPS` должен указывать на согласованный каталог Rust `release/deps` текущей сборки. `--install DIR` и `--fetch DIR URL` работают в отдельной папке и не используют сессии браузера. Интерфейс проверяется сценарием `scripts/check-workbench-ui.cjs` с изолированными данными на русском и английском.

Проверки и состав выпуска описаны в [релизе 0.9.8](release-0.9.8.md).
