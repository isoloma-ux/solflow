## Как устроен доступ

В проекте Sol Flow появляется панель MCP с отдельными разрешениями на расшифровки, саммери, карты и разборы. Все разрешения изначально выключены. После сохранения Sol Flow создает управляемый индекс `mcp-export/export.sqlite3` внутри своего каталога данных. Исходные `projects.json`, `meta.project` и `meetings/<id>/` сохраняют прежний формат.

Только Sol Flow читает оригиналы и обновляет индекс. Отдельный процесс `solflow-mcp` получает путь к индексу и открывает его для чтения. Он использует официальный Rust SDK RMCP 3.4.1 и транспорт stdio; не слушает сетевой порт. Каждое обращение открывает новый снимок данных и заново проверяет права. Это ограничение API, а не операционная песочница для процесса, запущенного от имени пользователя.

Сервер предоставляет пять инструментов:

| Инструмент | Результат |
| --- | --- |
| `list_projects` | Разрешенные проекты и состояние обновления |
| `list_recordings` | Готовые записи проекта, страницы до 100 записей |
| `search` | Фрагменты текста со ссылкой, датой, спикером, временем и ревизией; до 50 результатов |
| `fetch` | Фрагмент по ID с повторной проверкой прав; обнаружение изменения ревизии |
| `get_project_overview` | Название проекта, первая страница записей и состояние индекса |

Поиск поддерживает кириллицу, префиксы слов и фразы в двойных кавычках. Полноценной русской морфологии пока нет. Один фрагмент содержит до 2400 символов; время относится к исходному сегменту, а не к точному слову внутри длинного сегмента. Саммери, карты и разборы помечаются `generated: true` и не считаются дословной речью.

В индекс не входят аудио, настройки/ключи, история вопросов, переводы и незаконченные расшифровки. Сервер не записывает результаты в Sol Flow, не запускает микрофон, модели или загрузку URL. `stderr` содержит события обращения к инструментам без текста запросов и встреч; постоянного журнала в интерфейсе пока нет.

## Обновление и отзыв

Сохранение метаданных, расшифровки или разбора, перенос/удаление записи, изменение проектов и входящая синхронизация инвалидируют индекс. Фоновая очередь пересобирает его. Перед обновлением прежний доступный текст удаляется; при поврежденном или изменяющемся источнике индекс остается неактуальным, а ошибка видна в приложении. Для повторной попытки есть кнопка обновления. После перезапуска Sol Flow индекс также пересобирается.

Отзыв разрешения удаляет доступные MCP фрагменты проекта в транзакции и действует для следующих запросов без перезапуска сервера. Запрос, уже выполняющийся в момент отзыва, может завершиться. Уже полученный клиентом текст, его история и вручную созданные копии не отзываются.

Кнопка текстовой копии сохраняет **все сейчас разрешенные проекты** в `mcp-export/copies/<хеш>/`: Markdown-фрагменты и `manifest.json`, сопоставляющий их ID и имена файлов. Это отдельный явный экспорт, не источник для живого MCP. Пользовательские файлы рядом с индексом не удаляются. Копии остаются после отзыва.

Локальный сервер не делает внешних запросов, но клиент Claude может отправить полученный текст своему облачному сервису. Это объяснение показано перед выдачей доступа. Начинать следует с вымышленных встреч.

## Подготовка и подключение

Для разработки нужны Rust, Python 3 и обычные зависимости сборки Sol Flow. Из корня репозитория:

```sh
python3 scripts/check-mcp.py
python3 scripts/prepare-mcp.py
cargo check --locked --manifest-path desktop/src-tauri/Cargo.toml
```

`prepare-mcp.py` кладет исполняемый компонент с платформенным суффиксом в `desktop/src-tauri/binaries/`. Для установщика перед штатной сборкой Tauri выполнить `python3 scripts/prepare-mcp.py --release`. Компонент включен в `bundle.externalBin`; шаг добавлен в Windows/macOS workflows. Скрипты ничего не устанавливают, не подписывают и не публикуют. Если macOS требует лицензию полного Xcode, доступные Command Line Tools можно выбрать для конкретной команды через `DEVELOPER_DIR=/Library/Developer/CommandLineTools`; это не принятие лицензии Xcode.

Ручной пилот после подготовки отдельной проверочной сборки:

1. Создать проект с двумя вымышленными готовыми встречами и второй закрытый проект с отличимым секретным маркером.
2. В панели MCP первого проекта включить только расшифровки, сохранить и дождаться обновления. Второй проект оставить закрытым.
3. Нажать кнопку конфигурации Claude Desktop. Она показывает JSON с абсолютным путем к компоненту этой установки и аргументом `--export-dir`; существующие настройки клиента не изменяет.
4. По [официальной инструкции Claude](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop) добавить запись `solflow` в существующий объект `mcpServers`, сохранив другие серверы. Сделать резервную копию настроек и перезапустить Claude.
5. Спросить: «Сравни решения о бюджете в двух встречах. Для каждого изменения укажи название встречи, дату, спикера, цитату и таймкод». Проверить ответ по исходным фрагментам.
6. Проверить, что маркер закрытого проекта не находится, и отозвать разрешение первого проекта. Повторный вызов инструмента должен перестать возвращать его текст. Текст прежних сообщений в Claude останется.
7. Проверить ссылку `solflow://recording/<id>?t=<секунды>` в открытом и закрытом приложении. Обработчик открывает запись и позицию без автоматического воспроизведения. Регистрация системной схемы требует проверки установленного пакета; работа обработчика в коде не доказывает работу ссылки во всех клиентах.

Путь компонента должен быть постоянным; перенос приложения потребует обновления конфигурации. После первой выдачи разрешений MCP может читать последний подготовленный индекс при закрытом Sol Flow, но изменения синхронизации и отзыв выполняются самим Sol Flow. Не подключать произвольный каталог исходных записей вместо управляемого экспорта.

### Отдельный демонстрационный экспорт

Первый пилот сервера возможен до установки новой сборки Sol Flow. Пример `desktop/mcp-core/examples/demo_export.rs` создает только вымышленные данные в **новом** абсолютном каталоге; существующий каталог при создании отклоняется:

```sh
cargo run --locked --manifest-path desktop/mcp-core/Cargo.toml --example demo_export -- create /absolute/new-demo-directory
```

В конфигурации отдельного сервера `solflow-demo` указать абсолютный путь к `desktop/mcp-server/target/debug/solflow-mcp` и аргументы `--export-dir /absolute/new-demo-directory/export`. Для проверки отзыва заменить `create` на `revoke`, для восстановления — на `restore`, сохранив тот же каталог. Эти команды отказываются работать без маркера демонстрационного набора. Закрытый проект никогда не включается.

В текущем рабочем каталоге набор уже подготовлен в `.local-tools/mcp-demo-20260926/`, рядом лежит готовый `claude-config.json`. Проверено: создание дает два доступных фрагмента, отзыв — ноль, восстановление — снова два. Ожидаемый ответ: бюджет вымышленного запуска Альфа изменился со 100 до 120 тысяч рублей, срок — с пятницы на понедельник; источники — 12,5 и 42 секунды. Маркер «ФИОЛЕТОВЫЙ БАРСУК» из закрытого проекта не должен выдаваться. Ссылки этого набора не относятся к реальным записям установленного приложения: системные переходы проверяются отдельно.

## Что проверено

На Mac 26.09.2026:

- Сборка отдельного сервера; 7 тестов, включая реальный процесс SDK и обмен MCP, изоляцию закрытого проекта, живой отзыв, сохранность исходных байтов, поврежденные источники и отказ от симлинков. Поиск проверен на словах/префиксах и точных фразах.
- `cargo check` десктопа без стандартных возможностей и с ними; затем полный `cargo build --offline --locked` со стандартными возможностями и успешной линковкой. Это локальная debug-сборка, не подписанный установщик и не проверка запущенного приложения.
- `:app:compileDebugKotlin` Android; `scripts/check-safeguards.py`: 14 Rust и 42 Kotlin проверки.
- Панель проекта в настоящем браузере с вымышленным backend: выдача/отзыв, переключение проектов, конфигурация, RU/EN, отсутствие ошибок JavaScript. Это не проверка нативного Tauri IPC.

Еще не проверены: полный нативный сценарий, реальный Claude, системные ссылки Mac/Windows, Windows-блокировки, подпись вложенного компонента, чистая установка и обновление. Настройки реальных клиентов и пользовательские записи в этих проверках не изменялись. ChatGPT требует отдельной проверки способа подключения и прав аккаунта; готовая совместимость не заявляется.

Тесты с процессом запускаются именно через `scripts/check-mcp.py`: обычный `cargo test` пропускает помеченный `ignore` протокольный тест без собранного сервера. Не считать такой прогон полной проверкой MCP.
