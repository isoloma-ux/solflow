## Демонстрационное подключение

В пользовательский `~/.codex/config.toml` штатной командой `codex mcp add` добавлен включенный сервер `solflow-demo`. Транспорт — локальный stdio, исполняемый файл — `desktop/mcp-server/target/debug/solflow-mcp` из этого checkout. Аргумент `--export-dir` указывает исключительно на `.local-tools/mcp-demo-20260926/export`.

Перед добавлением сохранена приватная резервная копия `~/.codex/config.toml.before-solflow-20260926-165137.bak`. Существующие серверы не удалены. Отдельно отмечено автоматическое изменение `node_repl.args` при инициализации встроенного инструмента; его настройки не откатывались. `codex mcp get solflow-demo` подтверждает `enabled: true`, stdio и правильный путь к тестовому экспорту.

На этом первом демонстрационном этапе реальные записи, настройки Sol Flow, аудио и учетные данные не подключались. Туннель, публичный порт, платный API-вызов и Claude не использовались. Модель в клиенте обрабатывает переданный ей текст, поэтому «локальный MCP» не означает локальную модель.

## Проверенный сценарий

Реальный процесс сервера через JSON-RPC вернул пять инструментов. Поиск бюджета и `fetch` вернули две вымышленные встречи:

| Источник | Таймкод | Решение |
| --- | --- | --- |
| План — вымышленная встреча | 00:12,5 | 100 тысяч рублей, до пятницы |
| Уточнение — вымышленная встреча | 00:42 | 120 тысяч рублей, до понедельника |

Поиск секретного маркера закрытого проекта вернул ноль результатов, чтение его известного ID отклонено. При отзыве доступа без перезапуска сервера поиск перестал выдавать бюджет и чтение ранее полученного ID было отклонено. Для следующего шага доступ к двум вымышленным встречам восстановлен.

Машиночитаемое свидетельство: `.local-tools/mcp-demo-20260926/openai-pilot-preflight.json`. Это проверка MCP-протокола, **не вызовы инструмента моделью через интерфейс текущей задачи**.

## Проверка непосредственно из чата — пройдена

В следующем ходе 26.09.2026 инструменты `mcp__solflow_demo__*` появились в доступном каталоге и были вызваны моделью напрямую:

- `list_projects`: один разрешенный демонстрационный проект.
- `search` и `fetch`: обе бюджетные записи, правильные тексты, таймкоды и неизмененные ревизии.
- Поиск закрытого маркера: пустой результат; `fetch` закрытого ID: отказ.
- После временного отзыва разрешения демонстрационной утилитой повторные вызовы из чата дали пустой поиск и отказ чтения ранее доступного ID.
- После восстановления разрешения `list_recordings` снова вернул две записи. Демонстрационный доступ оставлен включенным.

Таким образом, чтение, поиск, изоляция и живой отзыв проверены через подключенные инструменты текущей задачи. Предыдущий файл `openai-pilot-preflight.json` остается свидетельством более ранней протокольной проверки; прямые вызовы зафиксированы в истории задачи.

## Официальные способы подключения

[Локальный MCP в Codex/приложении ChatGPT](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) использует общую конфигурацию и поддерживает stdio. Для [обычного ChatGPT через Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) понадобятся связанный с workspace туннель, соответствующие права Platform и режим разработчика. Этот второй путь в данном пилоте не настраивался.

Чтобы отключить только демонстрационный сервер: `codex mcp remove solflow-demo`. Это не удаляет тестовые файлы или записи Sol Flow. Не восстанавливать целиком старую конфигурацию поверх более поздних изменений.

В общем интерфейсе Mac/Windows добавлена основная кнопка «Скопировать запрос для подключения». Запрос содержит точные параметры установленного компонента, отдельную инструкцию для выбранного клиента, сохранение остальных подключений и резервную копию конфигурации. Помощник должен проверить initialize/tools/list и list_projects, не читая записи, и отделить проверенный результат от необходимости перезапуска. Автоматическое выполнение возможно только у помощника с доступом к файлам и процессам нужного компьютера. Само копирование ничего не устанавливает и не меняет разрешения.

Ручная настройка свернута: команда и каждый аргумент копируются отдельно без JSON/TOML-обертки. Полный блок оставлен отдельно с явным назначением «для файла настроек». Запрос, интерфейс и руководство доступны на русском и английском. Android использует общее руководство, но локальный MCP-сервер и настройка клиентов остаются на компьютере.

Проверено: 18 вариантов запроса для Mac/Windows и специальных символов, переводы, отдельное копирование и отсутствие изменения разрешений; браузерный интерфейс RU/EN; сборка и подпись Mac.
