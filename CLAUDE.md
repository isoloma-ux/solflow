# Sol Flow — правила разработки

## Паритет платформ (главное правило)

Sol Flow живет на трех платформах: Android (`app-android/`), Mac и Windows
(общий код в `desktop/`). **Любое изменение функциональности делается на
всех трех платформах в одном выпуске.** Прежде чем считать фичу готовой,
проверь: есть ли она на второй кодовой базе, и если нет — реализуй или
явно зафиксируй, почему нельзя.

- Если на какой-то платформе фича невозможна в том же виде (нет API,
  другая модель системы) — это решение записывается словами: в сообщении
  коммита и в списке задач, а не пропускается молча.
- Поведение должно совпадать по смыслу, а не по пикселям: очередь
  расшифровок, пауза записи, экспорт, отмены — одна логика везде,
  интерфейс — родной для платформы.

## Версия и выпуск

- Версия **общая на все три платформы**. Менять разом в трех местах:
  `app-android/app/build.gradle.kts` (versionCode + versionName),
  `desktop/src-tauri/tauri.conf.json`, `desktop/src-tauri/Cargo.toml`
  (после — `cargo update -w`, чтобы обновился Cargo.lock).
- Релиз = пуш тега `vX.Y.Z`: `release.yml` собирает Windows и Mac,
  `android.yml` — APK; всё складывается в один релиз GitHub, манифест
  `latest.json` ведет автообновление внутри приложений.
- Собирать релиз только с зеленого main.

## Окно «Что нового»

- Обновляется на обеих кодовых базах под фактический состав выпуска —
  без «это только на Android»: пользователь Windows читает про свою
  платформу.
- Пункты оформляются **списком с точками**, не абзацами через перенос.
- Окно ведет **историю версий**: перепрыгнувшему через релиз показываются
  и пропущенные разделы. При каждом релизе новая версия дописывается в
  начало истории: Android — список `history` в showWhatsNew
  (MainActivity) + строка `whatsnew_body_XYZ`; десктоп — блок
  `data-whatsnew-version` в index.html + переводы в i18n.js.
- Android: текст в `whatsnew_body` (values/ и values-en/), показ по
  versionCode в prefs. Десктоп: разметка в `ui/index.html`, показ по
  ключу `версия + WHATSNEW_REV` в localStorage — суффикс поднимается,
  если текст поменялся внутри той же версии.

## Языки

Каждая строка интерфейса живет на двух языках: Android —
`values/strings.xml` + `values-en/strings.xml`; десктоп — русский текст в
разметке/коде + перевод в `ui/i18n.js` (ключ — сама русская строка).

## Осознанные различия платформ

Зафиксированные исключения из паритета (правило: различие — только
записанное словами):

- **Локальной языковой модели на Android нет вовсе** (решение
  пользователя, 2026-09-01). Саммери: счёт 4B по длинной расшифровке
  вешал телефон вплоть до перезагрузки. Названия: 2.4 ГБ ради них
  бессмысленны, а маленькая Qwen3-0.6B выдаёт пустышки («Это встреча»).
  Саммери и названия считает десктоп; телефон их показывает (карточка
  и секция в экспорте остались) — приносит синхронизация (0.6.0).
- **Настройка «Саммери для записей с других устройств» есть только на
  десктопе** — следствие предыдущего пункта: телефону считать нечем.
  Остальная синхронизация (вход по коду, звук вкл/выкл, «Синхронизировать
  сейчас», отключение) одинакова на трех платформах.

- **Меню записи в сайдбаре и групповые саммери/названия — только десктоп**
  (0.7.0): на телефоне те же действия живут в открытой встрече (меню «⋮»,
  иконки в карточках) и в режиме выбора; саммери телефон не считает.
- **«Вопрос к записи» (чат с расшифровкой) — только десктоп** (0.8.0):
  отвечает та же локальная модель, что считает саммери, а её на телефоне
  нет. Ответы лежат в `qa.json` рядом со встречей и в синхронизацию не
  ходят: они привязаны к репликам и телефону показать их без модели
  можно, но спросить нельзя — решили не показывать вовсе.
- **«Поделиться» есть только на Android** (решение пользователя,
  2026-09-02): на телефоне системный лист «Поделиться текстом» уместен,
  на Mac и Windows это редко нужно — там экспорт в файл.

## Синхронизация (0.6.0)

- Протокол и раскладка на Диске описаны в `desktop/src-tauri/src/sync/mod.rs`
  и повторены в `app-android/.../SyncEngine.kt` — **менять только парой**.
- Ключи Яндекс OAuth — один файл `yandex-oauth.json` в корне: Rust читает
  его `include_str!`, gradle кладет в `BuildConfig`.
- Каждое сохранение `meta.json` ставит `updated` (millis) — на нем держится
  слияние конфликтов. Удаление встречи обязано пройти через
  `meetings::delete` / `MeetingStore.delete`, иначе не будет надгробия.
